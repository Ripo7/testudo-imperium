# Working on Testudo Imperium

Browser RTS in plain JavaScript ES modules, built with Vite, rendered with three.js 0.149.0 (pinned).

## Commands

- `npm run dev`: dev server. `npm run build`: production build into `dist/`.
- `npm run lint`: ESLint for mistakes only (undefined or unused names); a missing import is a runtime error that the build doesn't catch.
- `npm test`: lints, builds, then runs `tests/run.js` (map, params, smoke, controls, powers, determinism, headless, save & resume) in headless Chromium. Run one suite with `node tests/run.js smoke` after a build.
- `npm run balance -- 60`: AI-vs-AI wars, with the fog of war on (add `--nofog` for full information). Targets: each power wins 20–30%, median war 20–30 min (provinces are won whole, so wars run longer than under the old points rule), and as few wars as possible hit the 60-minute limit (about 1 in 20 does today).
- `npm run lab` (add `-- wars 200` for AI wars in Node, on every core): the battle, economy and war labs and their scorecard against `tools/lab/targets.js`. `npm run tune`: the tuner (`tools/tune.js`): fast (units, elites, combat, buildings with the two fast labs), then fair (one perk per power, rounds of wars), then a check on unseen seeds; `--apply` writes `balance.js` only if it does better. `npm run params -- list|set|diff|check`. The *Tune the balance* GitHub workflow runs the same at scale and can open a pull request.
- `npm run citylab`: the city lab page (every culture at every size, improvements and walls switchable, the far version). The `cities` test suite checks the generator in plain Node.
- `npm run audit -- 12`: usage count of every mechanic. If a change makes a mechanic unused or dominant, the audit shows it. Its probes in `tools/audit.js` match code text; update them when you rename that code.

## Module rules

- Every top-level declaration is exported, and imports are explicit and named.
- A module only assigns its own top-level `let` bindings. Other modules go through setters (`setMap`, `setME`, `resetPathfinder`, `resetCrest`), because ES imports are read-only.
- Module top-level code must not depend on other modules' constants at load time. DOM wiring and material patches that need other modules go in `init*()` functions, which `main.js` calls in order (`initHooks`, `initAtmosphere`, `initPanel`, `initScreens`).
- The simulation (`src/game/`, with `src/map/` and `core/math.js`) never imports the screen, the sounds or the browser. It reports what happens through `HOOKS` (`game/hooks.js`), which `initHooks()` in `ui/hud.js` fills in. A hook may show, sound or log, never change the game's state (the player's tally `GS.stats` is kept by the simulation). So the simulation runs in plain Node (`tools/headless.js`), and the headless test checks that a war played there is exactly the browser's. Browser tests run it with `setNoRender(true)` and call `simStep(0.1)` directly.
- `?test` loads `src/debug.js`, which exposes every export of every module (picked up automatically) as `window.__T`.
- Two terrain costs: `MAP.cost` is the builders' cost, used to lay out provinces and roads; changing it changes every map, and so breaks existing saves. `MAP.move` is the marching cost used by armies and pathfinding, and it can be tuned freely (`TERRAIN_MOVE` and `MOVE` in `map/generate.js`).
- Any power can be played: `PLAYER` (in `game/data.js`, set with `setPlayer`) is the human's power and `ME` is `PLAYER`, or `SPECT` in autoplay. Never hard-code Rome in texts: use `pName()`, `pAdj()` and `VOICE[PLAYER]`.
- Provinces and victory live in `game/standing.js`. A province belongs to a power only while it holds every place in it (`placesOf`: major city, towns, finished forts); otherwise it is free (`NEUTRAL`) or `DISPUTED`. `updateStanding()` recomputes it (`P.owner`, `P.holders`), records changes in the chronicle and bumps `PROV.version`, which repaints the map from the frame loop. Victory is `STAND.need` provinces (60%). Settlement points (`F.pts`, `F.share`) only drive overstretch.
- Every balance number lives in `game/balance.js`, pure data that the tuner rewrites. `game/params.js` gives each one (its path, e.g. `units.spear.atk`) a meaning, bounds and a group; a number with no rule stops the game at start-up. `data.js` builds the named units, elites, perks and buildings on top of those objects (prototype), and `COMBAT`, `BUILD`, `ECON`, `DIPLO`, `AI_PROV`, `ENDGAME`, `RIVALRY` are the same live objects, so `setParam` / `applyParams` change the game at once (same-seed experiments through `window.__T` or `tools/headless.js`). `node tools/params.js` lists, sets (writing `balance.js`), diffs and checks them.
- Never write a balance number into a text by hand: texts quote the values (`PERK_TEXT`, the improvements' `desc`, `sgnPct`/`pctOff`/`num` in data.js, `data-n` spans in the help screen filled by `drawHelp`).
- The record of the war lives in `game/chronicle.js`: events (`GS.chron`), samples of every power's points and men (`GS.hist`) and totals (`GS.fstats`). It is simulation state, so record from the simulation (never from UI hooks) and keep it deterministic. The Overview (`ui/overview.js`) and the end-of-war report (`ui/report.js`) only read it.
- Phones (`phoneLayout()`: at most 820 px wide, or 500 px tall when held sideways) get the compact HUD: a top strip, the dock (`#dock`, wired in `ui/hud.js`) and the panel as a sheet. On touch screens an order is planned by a first tap and given by a second (`UI.order`, `planOrder`/`confirmOrder` in `ui/state.js`, the standard in `ui/labels.js`); a long press adds an army to the selection or inspects. Mouse orders stay immediate (right-click).
- Soldiers have two levels of detail: the light procedural models in `render/crowds.js` everywhere, and close-up models (`render/models.js`, `src/assets/units/*.glb`) for armies within `NEAR_IN` of the camera. The close-up models are made by `tools/blender/units.py` from the base soldier and its skeleton (`tools/blender/soldier_base.py`); rebuild them with `python3 tools/blender/units.py` (needs `pip install bpy --break-system-packages`). The cities' landmark models likewise with `python3 tools/blender/landmarks.py`.
- Cities are drawn by `render/citygen.js` from the rules in `render/city/` (one module per culture, shared pieces in `kit.js`): `planCity(spec)` lays out streets and items (`{ kind, x, z, rot, w, l, seed }`), each culture's `*_BUILD` table draws an item kind with `add(geo, color, x, y, z, { ry, rz, scale })` in the item's own frame (front toward +z), `wallParts` draws the walls. Rendering only: never read or change the simulation from there. A city's culture is the nearest starting capital's (`cultureOf` in `cities.js`), fixed for the war. Landmarks come from the improvements (`LANDMARKS`) and only take ground from the houses: houses draw from a seed of their own (per block, `subRng`), never from the order things were placed, so a new building leaves the rest of the city as it was. Builders check `add.far` for the light version drawn from afar. Use `box` and `PANE` from `kit.js` (the frame scales one shared box). The Blender landmarks (`tools/blender/landmarks.py`, `src/assets/landmarks/*.glb`, loaded by `render/landmarkModels.js`) are placed with `model(add, key, x, y, z, width)`, which returns false until the model is loaded, so every landmark keeps a procedural fallback (the Node tests only see those). `spec.water` (`cityWater` in `cities.js`, from `riverLines()` in `water.js`) keeps houses off rivers and bridges the main streets. Check changes in `citylab.html` (`npm run citylab`).
- Fog of war lives in `game/sight.js`. Every power has a sight grid, updated inside `simStep`. The AI only uses what it sees (`knowsArmy`, `cityEstimate`, `estimateOdds(..., view)`). On screen, `seesArmy`, `seesBattle` and `seesCity` (`ui/view.js`) follow `viewer()`: the player's power, or the followed power in autoplay.

## Behaviour to preserve

- Determinism: the same map seed gives the same game. The simulation draws only from its own generator, `rnd()` and `rndIn()` in `game/state.js` (its state is `GS.rng`, saved with the game). Never use `Math.random` or the wall clock in `src/game/`; effects and sounds keep `Math.random`. Anything the simulation keeps between steps must go into the save, or the determinism test's save-and-load check fails.
- Saves must keep loading older saves. `game/save.js` turns the war into plain data and back (`snapshot`, `restoreSnapshot`); `ui/persist.js` adds the camera and speed and keeps it in the browser. Add new fields with defaults on restore rather than breaking the format (as `fillStats`, `chron` and `hist` do).
- Report charts use `FCHART` (in `ui/format.js`), steps of each power's colour checked for colour-blind separation on the dark tablet. Re-check with a palette validator if you change them.
- After a gameplay change, run `npm test`. For balance changes, also run `npm run balance` and `npm run audit`, and update the help screen in `index.html` when a rule changes.
